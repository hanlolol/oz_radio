OZ 라디오: 문장 병합 및 분리 가이드라인 (Draft)
단순히 마침표마다 기계적으로 자르는 것이 아니라, 아래 기준에 따라 데이터를 구성할 때 가장 자연스러운 '라디오' 경험이 만들어집니다.
1.	단편 문장 병합 (Short Sentence Merging)
o	기준: 개별 문장이 너무 짧아(예: 5단어 미만) TTS 재생 시간이 1~2초 내외일 경우.
o	효과: "안녕히 가세요. 문을 닫으세요."를 따로 듣는 것보다 하나로 묶어 듣는 것이 청취 피로도를 낮춥니다.
o	예시: 이번에 만족하셨던 "아주머니는 하던 일을 멈추고 문가로 나왔습니다. (중략) 알 수 있었습니다." 패턴.
2.	묘사 및 행동의 일치
o	기준: 주어의 연속적인 행동이나 긴밀하게 연결된 배경 묘사.
o	효과: 장면의 이미지가 뇌에 그려지는 동안 언어 노출이 끊기지 않게 합니다.
3.	대화문 분리 원칙
o	기준: 인물의 대사와 서술어는 가급적 분리.
o	효과: "'사이클론이 오고 있어!' (번역/원문)" 이후 잠시 쉬고 "그가 아내에게 소리쳤습니다"가 나와야 긴박감이 유지됩니다.

OZ 라디오 챕터 데이터 생성 매뉴얼 (v2.1)
본 문서는 오즈 라디오 프로젝트의 콘텐츠 제작 및 A/B 테스트를 위한 표준 가이드라인입니다. 모든 데이터는 이 규칙에 따라 다중 번역(문학적 번역/직역)을 포함한 JSON 형태로 구성되어야 합니다.
1. 기본 구조 (Data Schema)
데이터는 청취 호흡을 위해 문단(Paragraphs) 배열 내에 문장(Sentences) 배열을 포함하는 2뎁스 계층 구조를 가집니다.
•	파일 포맷: .json (UTF-8 인코딩)
•	경로 규칙: assets/data/book[번호]/chapter[번호].json
•	JSON 필수 필드:
o	book_id: 작품 식별자
o	chapter: 챕터 번호
o	paragraphs: 문단 객체들의 배열
	paragraph_id: 문단 순서 번호
	sentences: 문장(또는 청취 단위) 객체들의 배열
	sentence_id: 문단 내 문장 순서 번호
	original_text: 원문 (분리/병합 규칙이 적용된 텍스트)
	translation_literary: 자연스러운 문학적 의역
	translation_literal: 어순 유지 및 의미 단위 직역
[JSON 구조 예시]
JSON
{
  "book_id": "wizard_of_oz",
  "chapter": 1,
  "paragraphs": [
    {
      "paragraph_id": 1,
      "sentences": [
        {
          "sentence_id": 1,
          "original_text": "원문 문장입니다.",
          "translation_literary": "한국어 화자에게 자연스럽게 들리도록 다듬어진 번역입니다.",
          "translation_literal": "어순을, 유지하며, 의미 단위로, 번역된, 직역입니다."
        }
      ]
    }
  ]
}
2. 핵심 생성 규칙 (Content Rules)
① 문단(Paragraph) 구성 원칙
•	1:1 매칭: 원문의 한 문단은 반드시 JSON 내 하나의 문단 객체로 매칭되어야 합니다.
•	장면 중심: 하나의 문단은 하나의 완성된 장면이나 묘사를 담보하여, 청취자가 호흡을 잃지 않도록 합니다.
② 문장(Sentence) 병합 및 분리 (청취 리듬 최적화)
단순히 마침표마다 자르는 것이 아니라, **'청취 리듬'과 'TTS 재생 시간'**을 고려하여 sentences 배열 내의 단위를 구성합니다.
•	병합(Merging): 5단어 미만의 짧은 문장이 연속되어 TTS 재생 시간이 1~2초 내외일 경우, 하나의 객체로 묶어 청취 피로도를 낮춥니다.
•	분리(Splitting): 관계대명사나 접속사로 길게 이어진 복문은 인지 부하를 줄이기 위해 의미가 통하는 선에서 2개 이상의 객체로 나눕니다.
•	대화문 분리: 인물의 대사와 서술어는 가급적 분리합니다. (예: "사이클론이 오고 있어!"와 그가 아내에게 소리쳤습니다.를 별도 객체로 분리하여 긴박감 유지)
③ 다중 번역 작성 가이드 (A/B 테스트용)
각 sentence 객체는 다음 두 가지 버전의 번역을 동시에 제공해야 합니다.
A. 문학적 의역 (translation_literary)
•	문맥이 붕괴되지 않도록 한국어 어법에 맞게 자연스럽게 번역합니다.
B. 의미 단위 직역 (translation_literal)
•	어순 유지: 기계적인 1:1 단어 치환이 아닌 **'의미 단위(Chunk)'**로 묶어 원문의 어순을 최대한 따라갑니다.
•	TTS 친화적 기호 사용: 끊어 읽기를 유도할 때 슬래시(/)나 괄호() 등을 배제하고, 반드시 **쉼표(,)**만을 사용하여 TTS가 자연스럽게 반 박자 쉬고 넘어가도록 합니다.
•	가독성 유지: 최소한의 뜻은 유추할 수 있도록 해독 불가능한 비문(非文)은 피합니다.
④ 부가 요소 통제 원칙
•	별도 설명 멘트 금지: "이 문장은~", "다음은~" 등의 메타 설명이나 화자의 개입을 절대 포함하지 않습니다. 오직 원문과 번역문 자체만 데이터화합니다.
